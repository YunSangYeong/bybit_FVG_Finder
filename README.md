# FVG Precision V1.0

Bybit USDT 무기한 선물 전체 시장에서 확정 15분봉 FVG 후보를 찾는 React + TypeScript 앱입니다. 서버, API 키, 자동 주문 기능은 없습니다. 실제 시장 데이터 수집 실패 시 오류를 표시하며 가상 가격으로 대체하지 않습니다.

## 실행

Node.js 24 권장 (Vite 요구사항: Node 20.19+ 또는 22.12+).

```sh
npm ci
npm run dev
```

클라우드에서 기본 npm 캐시 경로에 쓰기 권한이 없으면 `npm ci --cache /tmp/fvg-npm-cache`를 사용합니다.

```sh
npm test             # 지표, 상태 머신, 인과성, API, 좌표 매핑 단위 테스트
npm run build        # TypeScript 검사 + 정적 빌드 → dist/
npm run preview      # 빌드 결과 로컬 확인
npm run test:e2e     # 모바일/데스크톱 Chromium 통합 테스트
```

E2E는 기본적으로 `/usr/bin/chromium`을 사용합니다. 다른 환경에서는 `CHROMIUM_PATH`에 설치된 Chromium 경로를 지정하거나 `npx playwright install chromium` 후 경로 설정 없이 실행할 수 있습니다. 테스트의 API 응답은 **검증용 고정 fixture**입니다. 앱에는 데모 데이터 경로나 테스트 가격이 포함되지 않습니다.

## 사용 방법

1. 거래대금(기본 1,000만 USDT), 방향, 최소 점수(75), 최근 신호 범위(10봉)를 설정합니다.
2. `전체 시장 검색`을 누르면 instruments-info의 모든 페이지와 24h tickers를 확인합니다. BTC는 제외하고 ETH는 선택적으로 포함합니다. 상위 몇 종목으로 제한하지 않습니다.
3. 종목별 15분봉/4시간봉을 각각 400개 요청합니다. 확정봉이 최소 300/250개보다 적으면 해당 종목을 분석 불가로 표시합니다.
4. READY가 기본 결과입니다. WAIT/TOUCH/INVALID도 상태 필터에서 선택할 수 있습니다. 설정은 localStorage에 저장됩니다.
5. 각 카드의 실제 캔들, FVG 박스, SWEEP/BOS/리테스트/READY 마커와 진입 화살표를 확인합니다. 점수 세부 내역과 TradingView 링크를 제공합니다.
6. 고급 설정의 FVG 크기·몸통 ATR 기준이나 추세 필터, 거래대금, ETH 포함 조건을 변경하면 다시 검색해야 분석에 반영됩니다. 점수·방향·상태·최근 범위·정렬은 수집한 결과에 즉시 적용됩니다.

모든 표시 시간은 KST이며 내부 시간은 UTC 밀리초, 차트 시간은 UTC 초입니다. 신호 시각은 해당 확정봉의 **마감 시각**입니다. 위험 비율(기본 0.5%)은 사용자 위험 관리 기준의 표시값이며 계좌 조회, 수량 산출 또는 주문을 실행하지 않습니다. 검색은 수동 스냅샷이며 자동 폴링/웹소켓이 아닙니다. 최신 상태를 보려면 다시 검색합니다.

## 분석 규칙과 미래 데이터 방지

- ATR14는 Wilder 방식, EMA는 기간 SMA로 시드합니다. 미확정봉은 분석에서 제외합니다.
- 피벗 좌우 2봉을 모두 확인한 시점에만 등록합니다. 스윕 당시 이미 확정된 피벗을 BOS 기준으로 복사해 고정합니다.
- `SWEEP → BOS → FVG 확정`의 엄격한 순서를 사용합니다. 스윕 이후 최대 10봉, BOS 이후 1~5봉 사이의 FVG만 등록합니다. BOS가 C2인 패턴은 지원합니다. BOS와 FVG가 동일 C3에서 동시에 성립하는 패턴은 제외합니다.
- 현재는 **스윕과 BOS가 모두 확인된 구조**만 후보로 등록합니다. 점수의 두 항목은 등록 후보에서 각각 20점입니다. 구조가 없는 단독 갭을 완화 후보로 추가하지 않습니다.
- 4시간 추세는 각 15분봉 마감 시각까지 확정된 데이터에서만 계산합니다. 추세 필터가 켜져 있으면 형성 시점과 READY 시점 모두 정렬·기울기 일치가 필요합니다.
- FVG는 C3가 닫힌 후 WAIT가 되고, C3 자체를 리테스트로 인정하지 않습니다. 이후 첫 터치만 사용하며 영역을 벗어났다 재진입한 반복 방문은 무효화합니다. 같은 봉에서 TOUCH와 READY 전환을 허용합니다. 첫 터치는 형성 후 1~10봉, 반전은 터치봉부터 터치 후 3봉까지 허용합니다.
- 경계 종가 이탈, 시간 만료, 반대 방향 유효 BOS는 진행 중인 후보를 무효화합니다. INVALID는 사유와 시각을 보존합니다.
- READY 당시 이벤트, 품질 점수, 손절 기준을 고정합니다. 미래 데이터가 추가되어도 과거 READY 자체를 다시 쓰지 않습니다. 다음 봉 시가가 없으면 READY 종가를 **예정 기준가**로 명시하며, 실제 다음 봉이 확보되면 그 시가로 진입/TP를 갱신합니다. 미확정 다음 봉에서 사용하는 필드는 시작 시각과 시가뿐입니다.
- READY 이후 경계 이탈/반대 BOS는 과거 READY 상태를 보존하면서 거래 상태를 INVALID로 표시합니다. 확정봉의 고저로 SL/TP 도달을 추적해 과거 완료 신호를 현재 후보와 구분합니다. 동일 봉에서 두 가격을 모두 통과하면 순서를 알 수 없으므로 `AMBIGUOUS`로 표시합니다. 수수료·슬리피지·갭 체결 가격을 모델링한 백테스트가 아닙니다.
- 롱 손절 기준은 READY 당시 확정 스윙 저점(없으면 스윕 저가), 숏은 확정 스윙 고점(없으면 스윕 고가)입니다. ATR 역시 READY 시점 값으로 고정합니다.
- READY 검색 범위는 READY 발생 봉을 기준으로 합니다. WAIT/TOUCH는 현재 유효 상태, INVALID는 무효화 발생 범위로 표시합니다. 신호 ID는 종목·방향·FVG C3 시간으로 중복을 막습니다.

### 사양의 점수 모순 처리

배점 항목의 최대 합은 100점이지만, 명세상 READY 신선도는 5점이 아닌 3점입니다. 따라서 **실제 READY 최대는 98점**, WAIT 최대는 90점입니다. 100점처럼 보이도록 임의로 정규화하지 않고 세부 배점을 그대로 적용했습니다. `gapATR`/`bodyATR`의 등록 임계값은 설정할 수 있지만 점수 기준(0.2/0.4, 0.8/1.2)은 명세대로 고정합니다. 점수는 성공 확률이 아닙니다.

## 차트

Lightweight Charts 5.3 API의 `addSeries(CandlestickSeries)`, `createSeriesMarkers`, `ISeriesPrimitive`를 사용합니다. 설치된 공식 타입 선언 및 공식 [Series primitives 문서](https://tradingview.github.io/lightweight-charts/docs/plugins/series-primitives)를 기준으로 구현했습니다.

FVG 박스는 차트 프리미티브가 매번 시간·가격 변환 API를 호출해 그립니다. 확대/스크롤/리사이즈 때 차트의 좌표계를 따릅니다. 이벤트는 `atPriceMiddle` 마커로 실제 이벤트 가격에 고정합니다. 차트는 기본 최근 80봉을 중심으로 스윕과 신호를 포함하도록 범위를 확장합니다. EMA50/200 표시는 **15분봉 EMA**이며 분석용 4시간 추세 EMA와 구분합니다. WAIT/TOUCH에는 진입/SL/TP를 그리지 않습니다. IntersectionObserver로 화면 근처의 차트만 만들고 화면을 벗어나거나 카드를 접으면 해제합니다.

TradingView Lightweight Charts™는 TradingView의 상표이며 Apache-2.0 라이선스 라이브러리입니다. 차트의 출처 로고와 하단 TradingView 링크를 유지합니다.

## API·오류·네트워크

필요 도메인: `api.bybit.com` (HTTPS). 공개 `/v5/market/instruments-info`, `/tickers`, `/kline`을 사용합니다. 외부 폰트나 별도 프록시 서버를 요구하지 않습니다.

- HTTP 요청 최대 동시 5개, 타임아웃 12초, 일시 네트워크 오류/429/5xx 최대 4회 시도, 0.5/1/2초 지수 백오프.
- 검색 취소, 일부 종목 실패 후 계속 처리, 실패 사유 표시.
- OHLCV 숫자/범위/시간/거래량 검증, 중복 제거, 정렬. 중간 봉 누락 또는 상충하는 중복이 있으면 해당 분석은 실패 처리합니다.
- 403은 지역 또는 네트워크 정책을 확인하도록 표시합니다. 브라우저의 CORS 오류와 네트워크 차단은 JavaScript에서 세부 원인을 구분할 수 없어 가능한 원인을 함께 표시합니다.
- 클라우드에서 `api.bybit.com`에 대한 실제 접속은 **프록시 CONNECT 403**으로 차단되었습니다. 허용 도메인 초안에 추가했지만 초안 저장은 현재 네트워크에 적용하거나 게시하지 않습니다. 환경 설정에서 검토·저장한 후 다시 검증해야 합니다. 지역 제한이 남으면 해당 지역 브라우저에서도 실데이터를 사용할 수 없습니다. 임의 대체 도메인이나 우회 프록시를 사용하지 않습니다.

## GitHub Pages

`.github/workflows/deploy.yml`은 main push 또는 수동 실행 시 `npm ci`, 테스트, 빌드 후 Pages 아티팩트를 배포합니다. `vite.config.ts`는 Actions에서 `GITHUB_REPOSITORY`의 저장소 이름으로 base를 자동 설정합니다.

1. 변경 사항을 GitHub main에 반영합니다.
2. 저장소 Settings → Pages → Source를 **GitHub Actions**로 설정합니다.
3. Deploy to GitHub Pages 워크플로를 실행합니다.
4. 성공한 workflow의 `github-pages` deployment URL에서 확인합니다.

기본 예상 URL: https://YunSangYeong.github.io/bybit_FVG_Finder/

이 URL은 **배포 완료가 확인된 주소가 아닙니다**. 이 작업에서는 push, Pages 활성화, 실제 배포를 수행하지 않았습니다. 사용자 도메인/저장소 Pages 설정에 따라 달라질 수 있습니다. 공개 배포 후 사용자 지역의 Bybit API 및 브라우저 CORS 접근을 별도로 확인해야 합니다.

## 검증 범위

단위 테스트는 FVG 양방향, ATR/EMA, 스윕, 피벗 지연, BOS, 사건 순서, 상태 전환/만료, 중복 방지, 점수, 롱숏 위험 가격, 미래봉 추가 전후 과거 READY 보존, API 페이지네이션/재시도/필터/정규화, 차트 좌표/마커를 검증합니다.

브라우저 테스트는 고정 API fixture로 모바일 전체 검색→결과 카드→캔들 캔버스→EMA→확대→접기/펼치기→설정 유지, 403 표시, 데스크톱 레이아웃을 확인합니다. 테스트 fixture 통과가 실시간 API 연결 성공을 의미하지 않습니다. 기존 1파 탐지기 소스나 화면이 제공되지 않아 요청된 정보 구성을 기반으로 새 UI를 구현했습니다.
